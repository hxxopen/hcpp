# HCPP Protocol — Versioning

**协议版本**：0.1  
**文档版本**：SPEC-0.1.0  
**状态**：Draft  
**最后更新**：2026-09-04

---

## 1. 概述

本文件是协议层面的版本规则说明，与仓库根目录的 [VERSIONING.md](../VERSIONING.md) 互补。

根目录 VERSIONING.md 面向贡献者与实现者，说明整体版本策略；本文件聚焦 **Provenance Record 中的协议版本字段** 及其兼容性要求。

---

## 2. 协议版本字段

每条 Provenance Record **必须**包含：

```json
{
  "hcpp": "0.1"
}
```

- 字段名：`hcpp`
- 类型：string
- v0.1 的值固定为 `"0.1"`

验证器必须读取此字段，并据此选择对应的解析、校验与兼容逻辑。

---

## 3. 版本号格式

协议版本采用 `Major.Minor` 形式（字符串）：

- `0.1`、`0.2`、`1.0`、`1.1` …

不在此字段中体现修订号（patch）。修订号仅用于文档与实现版本。

---

## 4. 兼容性规则

### 4.1 次版本（Minor）升级：0.1 → 0.2

允许：

- 新增可选字段
- 新增关系类型
- 新增推荐算法（旧算法仍可用）
- 扩展枚举值（向后兼容方式）

要求：

- 旧版本记录必须能被新版本验证器正确处理
- 不得删除或改变已有字段的语义

### 4.2 主版本（Major）升级：0.x → 1.0 或 1.x → 2.0

允许：

- 字段删除或重命名
- 语义变更
- 强制算法迁移
- 结构性调整

要求：

- 新验证器应能识别旧版本号，并明确报告“版本不受支持”或提供有限的向后处理能力
- 历史记录的密码学有效性不得被无故破坏

---

## 5. 验证器行为要求

实现 MUST：

- 读取并尊重 `hcpp` 字段
- 对不支持的协议版本给出明确错误，而不是静默错误解析
- 在支持范围内正确验证历史版本记录

实现 SHOULD：

- 同时支持当前版本与至少一个前序次版本
- 在验证结果中返回实际使用的协议版本

---

## 6. 与文档版本、SDK 版本的关系

| 类型 | 示例 | 说明 |
|------|------|------|
| 协议版本 | `0.1` | 写入 Record 的 `hcpp` 字段 |
| 规范文档版本 | `SPEC-0.1.0` | 文档自身版本 |
| SDK 版本 | `go-sdk/v0.3.1` | 与协议版本解耦 |

SDK 应声明其支持的协议版本范围，例如：

```text
Supports HCPP protocol versions: 0.1, 0.2
```

---

## 7. 废弃与过渡

当需要废弃某字段或算法时：

1. 在规范中标记为 Deprecated，并说明替代方案。
2. 至少保留一个次版本的过渡期（v1.0 之后更严格执行）。
3. 验证器在过渡期内对已废弃特性给出警告而非直接失败。
4. 正式移除只能在新的主版本中进行。
